# Indexer — Invariants, Business Logic, and Security

This document describes **on-chain indexing** and **read-only HTTP API** behavior for [`indexer/`](../indexer/). It pairs with [contracts-security-audit.md](./contracts-security-audit.md) (on-chain) and [security-model.md](./security-model.md) (protocol).

## Architecture

- **Indexer task:** LCD → parse txs → Postgres (swaps, candles, traders, positions, limit fills and lifecycle rows, liquidity events, hooks, oracle rows).
- **API task:** Axum handlers (primarily `GET`) → SQLx (parameterized) → JSON; `POST /api/v1/route/solve` for hybrid-aware route merge and optional LCD simulation.
- **Shared state:** `AppState` (pool, LCD client, USTC price cache, ticker map cache, orderbook cache, optional `router_address` for route simulation).

### Local dev CORS: `localhost` vs `127.0.0.1` {#local-dev-cors-localhost-vs-127001}

The browser sends `Origin` using the hostname from the address bar. `http://localhost:5173` and `http://127.0.0.1:5173` are different origins; if `CORS_ORIGINS` lists only one of them, fetches from the other fail CORS even when the indexer returns **200**. Include both spellings (and Vite preview ports if used) in dev — see [`indexer/.env.example`](../indexer/.env.example), [`scripts/deploy-dex-local.sh`](../scripts/deploy-dex-local.sh), and [GitLab **#131**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/131). Dedicated Playwright Vite (`PLAYWRIGHT_WEB_PORT`, default **3173**) is another Origin — LocalTerra deploy and [`scripts/e2e-start-indexer.sh`](../scripts/e2e-start-indexer.sh) merge it via [`scripts/lib/indexer-cors-playwright.sh`](../scripts/lib/indexer-cors-playwright.sh) ([#625](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/625) leftover #2 / **M625-3**). After placing a limit, the dApp polls `limit-placements`; failures are logged as **`[limit-place] indexer poll failed:`** via [`warnIndexerPlacementPollFailed`](../frontend-dapp/src/utils/warnIndexerPlacementPollFailed.ts). The **`/trade`** ticket’s **View order** affordance scrolls to indexed placement rows keyed by `order_id` ([GitLab **#161**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/161); [`docs/frontend.md` § Trade page — limit place success affordances](./frontend.md#trade-page-limit-place-success-affordances)).

**Remote soft-launch hosts from local Vite:** do not widen production `CORS_ORIGINS`. Use the Vite same-origin proxy (`/__dev/indexer`, `/__dev/lcd`) — [`docs/frontend.md` § Local CORS proxy](./frontend.md#local-dev-remote-cors-proxy), [`skills/AGENTS_FRONTEND_LOCAL_REMOTE_CORS_PROXY.md`](../skills/AGENTS_FRONTEND_LOCAL_REMOTE_CORS_PROXY.md).

## Frontend expectations (read path)

The indexer may legitimately return **empty candle arrays** for a pair/interval with no buckets yet. The dApp must treat that as **success**, not a silent chart failure. UI invariants and lightweight-charts vs TradingView widget naming are documented under [Trade page — price chart invariants](./frontend.md#trade-page--price-chart-invariants) (GitLab [**#113**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/113), [**#150**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/150)).

When validating LocalTerra flows with **browser wallets**, fee broadcast quirks are **frontend/wallet** concerns — on **LocalTerra** use **Terra Classic Keplr** or the **dev/simulated wallet** for gas/fee verification; **do not use Terra Station** (built-in stale **`localterra`** gas step — not fixable by dApp overrides alone; [GitLab **#235**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/235), [`docs/frontend.md` § Station extension signing](./frontend.md#station-extension-signing)). **Terra Station P0** belongs on **columbus-5**. Mitigations still in code for columbus-5 / when Station fixes LocalTerra: **`addNetwork` gas refresh**, **`experimentalSuggestChain`**, **per-sign `preferNoSetFee` + post-sign guard vs `stdDoc.fee`** in patched cosmes **`KeplrExtension`**, **Station extension → amino signing** in patched **`StationController`**, **min gas price**, **`npm ci` / `cosmesPatch127.test.ts`** — [`docs/frontend.md` § Terra Classic gas limits](./frontend.md#terra-classic-gas-limits), GitLab [**#127**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/127)); the indexer only observes txs once included on-chain.

**Pair pause vs limit claim:** On-chain **`ClaimExpiredLimitOrder`** is rejected while the pair is paused (same **`assert_not_paused`** gate as cancel — [contracts-security-audit.md](./contracts-security-audit.md) **L6**, GitLab [**#120**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/120)). Bots and UIs must not broadcast claim txs during a pause; the dApp mirrors this on **Claim refund** ([`skills/AGENTS_FRONTEND_LIMIT_PARKED_EXPIRED.md`](../skills/AGENTS_FRONTEND_LIMIT_PARKED_EXPIRED.md)).

**Router `simulate_swap_operations` vs spread:** Route solve responses (and the dApp’s matching wallet LCD `simulate_swap_operations` query) carry **router_operations** plus an optional **`estimated_amount_out`**, but the router simulation payload does **not** include per-hop **spread** — only the final amount. The retail Swap page therefore runs a **sequential pair-level preflight** (factory + `simulation` / `hybrid_simulation`) so **price impact** and submit gating align with on-chain **`max_spread`** per hop. **Route preview:** when both the indexer graph and the client BFS can describe the same hops, the UI must not show duplicate “indexer vs client” route lines — the path shown must follow the operations used at submit ([GitLab **#158**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/158), [`skills/AGENTS_FRONTEND_SWAP_ROUTE_DISPLAY.md`](../skills/AGENTS_FRONTEND_SWAP_ROUTE_DISPLAY.md)). Invariants and agent notes: [swap max spread / price impact UX](./swap-max-spread-ux.md) (GitLab [**#134**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/134)), [`docs/frontend.md` § Swap Page Integration](./frontend.md#swap-page-integration), [`skills/AGENTS_LOCALNET_TRADING_SWARM.md`](../skills/AGENTS_LOCALNET_TRADING_SWARM.md).

**Retail GET default (Swap + Trade market, [#501](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/501), always-on [#596](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/596)):** Both `/` Swap and `/trade` Market CW20 quotes call **`GET /api/v1/route/solve`** (shared [`quoteCw20ViaRouteSolve`](../frontend-dapp/src/utils/cw20RouteSolveQuote.ts)) and submit the solver’s per-hop `hybrid` from `router_operations`. ## Attack paths (off-chain API)

1. **Query injection via `sort` / `interval`** — Blocked by allowlists (no string pasting into SQL for those).
2. **Ticker confusion / extra underscores** — Blocked by strict `BASE_TARGET` shape (exactly two non-empty segments).
3. **DoS: huge limits** — Blocked by caps on trades, candles, hooks, oracle history, CG trades, orderbook depth.
4. **DoS: expensive DB per request** — Ticker map cache reduces repeated full scans for CG/CMC; `/overview` whole-response cache (60s) + O(1) `global_stats_24h` rollup read on cache miss (**#333** / **#281** / **#550** / **#569** / **#586** / **#652** / **#668**). 7d/30d/active-pair/unique-trader **and** pool TVL / Δ% **and** fee totals **and** volume prior-window Δ% are materialized — never live-scanned per GET (no `pair_reserves` join, no `global_liquidity_snapshots` walk, no `protocol_fee_events` / `swap_events` / fills `SUM` on the request path). `GET /protocol/fees` reads capped child rollup tables (60s cache; `window` allowlist). `GET /api/v1/protocol/volume/daily` reads hourly/daily/monthly rollup tables only (60s cache; `days` allowlist `7` \| `30` or `grain` + capped `limit` — **#652** / **#668**). `GET /api/v1/defillama/daily` reads `defillama_daily_*` only (60s cache; single UTC-day `timestamp` — **#631** / A11–A12). Snapshot prune 35d; Protocol daily retain 95d; hourly ~10d; monthly ≥ 24 months.
5. **DoS: LCD hammering via orderbook** — Short-TTL cache on simulated orderbook.
6. **DoS: connection exhaustion** — Rate limit + timeout (defense in depth; edge still needs WAF/reverse proxy).
7. **Information leak via errors** — `internal_err` for DB paths; **`lcd_gateway_err`** for LCD proxy paths (**#239** / H6).
8. **LCD amplification abuse** — Per-request query budgets + **`RATE_LIMIT_LCD_HEAVY_RPS`** on limit-book, CG/CMC orderbook mirrors, and route solve (**#239** / H7, **#278**).
9. **CORS token theft** — Browser enforces origin; server only echoes allowlisted origins.

## Block time resolution (GitLab #243)

Block timestamps for indexing come from the LCD transaction response (`tx_responses[0].timestamp`) when valid RFC3339. In [`indexer/src/indexer/block_indexer.rs`](../indexer/src/indexer/block_indexer.rs), `resolve_block_time`:

- Parses tx timestamp into UTC when valid.
- If the tx timestamp is **missing** or **invalid**, retries using the LCD **block header** `time` for that height.
- If **both** are unusable, block ingest **fails** (cursor unchanged) — **no** `Utc::now()` wall-clock fallback.

**Risk mitigated:** Event times and candle bucket boundaries no longer skew to ingestion wall clock when LCD tx metadata is bad but header time is good.

- Run a **reliable LCD** close to your chain; monitor logs for `Invalid tx timestamp` / `Missing tx timestamp` / `Block header time missing or invalid`.
- After prolonged LCD issues, consider **re-indexing** from a known height (see [runbook: reorg / replay / dedup](./runbooks/indexer-reorg-replay-dedup.md)).

## Overview global stats (GitLab #281, #333)

`GET /api/v1/overview` exposes cross-pair volume/trade totals from [`get_global_stats`](../indexer/src/db/queries/volume.rs), which reads the materialized **`global_stats_24h`** table on cache miss (migrations `indexer/migrations/20260605120000_global_stats_24h_rollup.sql`, `20260818120000_global_stats_windows_and_census.sql`). Unlike `pair_volume_24h` (quote-side `SUM(return_amount)` per pair), this rollup stores the exact global semantics: `SUM(offer_amount)`, `COALESCE(SUM(volume_usd),0)`, `COUNT(*)`, plus 7d/30d USD, 24h active pairs, and unique traders ([#550](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/550)). **`volume_usd` ingest** is P522-Q / hub USD (#548 / #556); Charts does not display raw `total_volume_24h`. When trades > 0 and priced USD is 0, the JSON field is `null` so the UI can show `—`. Do **not** convert DEX volume with vFDUSD.

**Layers:**

1. **Rollup table** `global_stats_24h` — refreshed every **~5 minutes** by the volume aggregator (same loop as `pair_volume_24h`). Bounds cache-miss latency to an O(1) primary-key read. A successful refresh **decreases** 24h totals when swaps age out of the window ([#577](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/577) **D4**). If `updated_at` is **>15 min** old, the indexer **logs a warning** and still serves the rollup — never a GET-path 30d scan (**D6**). See [runbook § freshness](./runbooks/overview-global-stats-brin.md).
2. **60s response cache** on the whole `/overview` JSON — bounds latency for request bursts regardless of table size.
3. **BRIN index** `idx_swaps_block_timestamp_brin` on `swap_events(block_timestamp)` — safety net for optional live aggregate (`OVERVIEW_GLOBAL_STATS_LIVE=1`); production tuning in [runbook: overview global stats & BRIN](./runbooks/overview-global-stats-brin.md).

`pair_count` is still computed live from `pairs` on each cache miss. Reorg/replay safety follows the same ingestion guards as pair volume rollup (**C3** hash guard, swap dedup).

## Dapp read model (pools list)

The Liquidity pool browser (`/pool`) **lists and sorts** pairs from the indexer API; it **tags** each row against the on-chain factory pair set used for the swap router graph. Counts and badges are documented in [Frontend guide — Liquidity pools list (indexer vs factory)](./frontend.md#liquidity-pools-list-indexer-vs-factory) (see [glab#112](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/112)).

### Factory LCD: pair enumeration vs governance gas (agents)

When the indexer (or any tool) syncs pairs from the factory via LCD, use **paginated** `Pairs` / `GetPairCount` and **avoid** assuming unbounded factory queries are cheap on-chain—the factory keeps a sequential `pair_index` for **O(limit)** page reads, while **`start_after`** (asset pair cursor) resolves in **O(1)** via `pair_key_idx` ([GitLab **#258**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/258); see [Smart contract reference — Factory storage & upgrades](./contracts-terraclassic.md#factory-storage--upgrades)). That design is separate from **per-pair governance** messages (`SetPairFee`, `SweepPair`, etc.), which must use an **O(1)** reverse map (`pair_addr_reg`) so gas stays bounded at high pair counts ([GitLab **#122**](https://gitlab.com/PlasticDigits/cl8y-dex-terraclassic/-/issues/122)). Third-party agents should follow the same split: iterate for **listing** only; never reintroduce linear “is this pair registered?” scans in contract code paths that validate a single address—see [`skills/AGENTS_TERRACLASSIC_GAS.md`](../skills/AGENTS_TERRACLASSIC_GAS.md).

When adding a new query parameter that influences SQL or ordering:

1. Use an allowlist or parameterized query only.
2. Cap numeric inputs.
3. Add a **happy** and **unhappy** test (400/404/429 as appropriate).
4. Update this matrix if the invariant is user-visible.
