The DEX core remains **defense-in-depth** under the documented trust model (honest governance, whitelisted non-FoT CW20s, factory-provenance ingest). No **Critical** unauthorized fund-loss path was found on current `main`. Request-count limits **do not** equal cost limits. The findings below are “one request, too much work.”

### RE-01 — Medium: `/gt/events` unbounded rows + full `pair_reserves` read

**Where:** `indexer/src/api/gt.rs` (`MAX_EVENT_BLOCK_SPAN = 2000`; queries at the events handler).

Block span is capped, but swap and liquidity `SELECT`s have **no `LIMIT`**. After those, the handler loads **every** `pair_reserves` row (`SELECT pair_id, reserve_0, reserve_1 FROM pair_reserves`) to stamp current reserves onto events.

**Impact:** A busy 2 000-block window can return a multi-MB JSON payload and run heavy JOINs. Repeated at global 60 RPS this is a classic API4 export/DoS. GeckoTerminal is a public listing surface; abuse degrades quotes for all users.

**Tests:** Range rejection only (`tests/api_gt.rs`). No row-volume or reserve-scan test.

**Fix:** Hard `LIMIT` (e.g. 5 000 events) + 413/400 when exceeded; project reserves for pairs present in the window only; consider LCD-heavy or a dedicated GT governor.

### RE-02 — Medium: `/route/solve/progress` is not LCD-heavy and may call LCD

**Where:** `indexer/src/api/mod.rs` (progress on the **global** router after `merge(lcd_heavy_router)`); `route_solve_progress.rs` → `resolve_discount_bps` (`route_solver.rs`).

`GET /route/solve` is on the 10 RPS LCD-heavy router. Progress is a separate route at **60 RPS**. If `trader`/`sender` is set and `fee_discount_address` is configured, each poll can `query_contract` the on-chain registry.

**Frontend amplifier:** `useRouteSolveProgress` polls ~1 Hz while a sim quote is in flight (`frontend-dapp/src/hooks/useRouteSolveProgress.ts`), and Swap/Trade also refetch quotes on an interval.

**Impact:** Honest UI already multiplies LCD load. An attacker can do the same at 60 RPS with distinct `trader` values (cache key includes trader) → public LCD amplification and indexer worker saturation. Route-solve itself is cached; **progress + live `GetDiscount` is the hole**.

**Tests:** Lifecycle only. **No 429 test** for progress or for `/route/solve` itself in `security.rs`.

**Fix:** Put progress on the LCD-heavy router; cache `discount_bps` per trader (reuse the 12s route cache); skip LCD when the registry snapshot is already in the progress entry.

### RE-03 — Medium: `blacklist-check` unbounded lists on the global limiter

**Where:** `indexer/src/api/compliance.rs`; routed on the global router.

`tokens` and `pairs` are comma-split with **no max length**. The whole vectors are forwarded to factory `BlacklistCheck` on LCD.

**Impact:** One HTTP request can force a large CosmWasm query. At 60 RPS this is LCD amplification distinct from RE-02. dApp CTAs depend on this probe; saturation looks like “DEX down.”

**Tests:** Sanitized 502 only (`security.rs`). No list-cap or 429 test.

**Fix:** Cap e.g. 16 tokens / 8 pairs; reject oversize with 400; move to LCD-heavy.

### RE-04 — Low–Medium: browser refetch intervals as a friendly botnet

Swap, Trade, Pool, Portfolio, Charts, Protocol, and limit-status hooks use `refetchInterval` of 15–60s. Progress adds ~1 Hz during slow quotes. Behind NAT, `PeerIpKeyExtractor` shares one bucket — honest users and attackers look the same.

**Impact:** Not a theft vector. Combined with RE-02/RE-03 it turns a few open dApp tabs into sustained LCD/indexer load. Quote debounce (`quoteDebounce.ts`) skips overlapping sim refetches — good — but progress is independent.

**Fix:** Back off progress after N misses; do not pass `trader` on progress if discount is already in the in-flight quote; consider a shared client-side budget.

### RE-05 — Low: F6 freeze cache fail-open (availability vs safety)

**Where:** `indexer/src/indexer/asset_code_id_freeze.rs`. Execute paths fail-closed on-chain. Indexer `is_pair_code_id_frozen` returns **false** if the mutex is poisoned; LCD/`GetAssetCodeIds` failures keep last known or treat never-seen pairs as tradable.

**Impact:** A probe outage can put a newly frozen pair back into `/route/solve` for up to the 60s probe interval (or longer if the probe stays down). Users sign txs that revert (gas loss). Inverse of the old “always quote frozen” bug — #585 fixed the steady state, not the fail-open window.

**Tests:** Unit tests for pin/whitelist verdicts; integration `route_solve_excludes_code_id_frozen_pair`. No fail-open / poison test.

### RE-06 — Low: on-chain leftover exhaustion (bounded per tx, not free)

| Vector | Status |
|--------|--------|
| Expired-limit head clog (`MAX_SCAN_STEPS` 500) | Bounded; taker may spill to pool (**M-03**, #289). Mitigated by `book_start_hint` + `CleanLimitBook`. |
| Permissionless observation growth to 65 000 | Caller pays gas; pair storage grief (**L-03**). |
| Unbounded hook list | Governance-only; each swap queries every hook (**AMM-03**). Still **no cap**. |
| AutoLP `SkimToLp` | Permissionless; bounded by pair swap+provide; floor exists (#610). |
| `CreatePair` 1/block + 100 LUNC fee | Economic spam gate; listing-spam freeze still cheap vs ops cost (Chain E). |

### RE-07 — Info: tokens `limit=500` and leaderboard cache bust

Token list allows 500 rows (2.5× pairs). Leaderboard cache clears at 64 distinct sort/limit/pair keys. Mitigated by TTL and row caps. **No** `security.rs` upper-cap test for tokens.

### C-01 — Medium (governance): unbounded hook list — gas grief of every swap

**Where:** `pair/src/contract.rs` `execute_update_hooks` — validates addresses, saves the `Vec`, **no max length**.

A reverting allowlisted hook still rolls back the whole swap (intentional, **H1**). Dozens of *succeeding* hooks add `GetConfig` + settlement work per swap until the tx hits the block gas limit → pair halt without an explicit pause.

**Still active** from AMM-03 / SUP-07. **Test:** revert-on-hook covered; count cap **not** tested.

**Fix:** Cap `hooks.len()` (≤5–10) on `UpdateHooks`.

### C-02 — Medium (economic): pair TWAP is manipulable on thin pools

**Where:** `dex-common/src/oracle.rs`; pair records pre-action reserves. `Observe { seconds_ago: 0 }` uses live `RESERVES` (AMM-05). Extreme ratios skip writes (AMM-06). Docs already say consumers need ≥30m windows and a TVL floor.

**Settlement does not use this TWAP.** UST1 window `effective_swap` is out-of-repo. Hub USD and dApp charts can still mislead.

**Tests:** Happy-path oracle tests; **no** multi-block manipulation sim (gap vs 2026 checklists).

### C-03 — Medium (accepted design): 300s fee-discount cache (P9)

A wallet that drops below its CL8Y tier keeps the cached discount until TTL. Bounded fee leakage. Flash-loan tier gaming (SUP-05) is **theoretical** — no in-repo CL8Y lending. Still undocumented as a consumer-facing economic property.

### C-04 — Medium (tokenomic): T9 self-cross cheaper than pool (F-05) + 0-bps placement (F-06)

Still active from `1786830980`. Placement uses `limit_discount_bps`; take/swap uses `discount_bps`. T9 placement can be 0 bps — dust-spam floor removed; 300s cache amplifies. Self-crossing the book undercuts the pool fee.

**Not a theft bug.** Treasury revenue and book quality degrade. No anti-Sybil on leaderboards (POS-02).

### C-05 — Medium (liveness): F6 maximal freeze still gates exits

Cancel / claim / withdraw still require live pin + whitelist. A listed-token wasm admin can freeze **all** user value in that pair until governance refreshes. Documented tradeoff after #584; unfreeze-arb (stale reserves vs CEX) remains (Chain A).

Indexer now **excludes** known-frozen hops (#585) — the `1787230030` “always quote frozen” High is **partially fixed**. RE-05 is the remaining fail-open window.

### C-06 — Low: permissionless observation cardinality to 65 000

Caller-paid storage grief. Test exists for the cap, not for economic grief.

## 4. Indexer / database / API

### 4.1 SQL injection and error leaks — good

Dynamic `ORDER BY` / interval / ticker fragments are allowlisted. Community-token SQL is parameterized. Pair search uses `QueryBuilder` + `escape_like_pattern`. DB errors become `"Internal server error"`; LCD errors become `"Upstream LCD query failed"`. Startup logs omit `DATABASE_URL`. `tests/security.rs` covers the main injection and leak cases.

**No SQLi finding.** SEC-D08 from the 2026-07 SEC-J deferral is largely closed in code; a `%`/`_` abuse test for pair search is still missing.

### I-01 — Medium: non-transactional ingest + reorg halt without rollback

**Where:** `block_indexer.rs` / `poller.rs`. Hash mismatch → `emit_reorg_halt` and **process exit**. Recovery is the operator script (`indexer-reorg-recover.sh`). Trader/position rollups are not height-keyed (REORG-02). Parser `parse_asset_amounts` uses `unwrap_or_default()` — invalid amounts become **zero** (PARSER-01/02).

**Impact:** After a Terra Classic reorg or a mid-block parse skip, candles, volumes, leaderboards, and hub USD can stay wrong until a human replays. Combined with oracle staleness, the dApp presents stale-as-live.

**Still active** from `1785897304`. Tests cover halt + webhook, not rollup rebuild.

### I-02 — Medium: CEX/Venus oracle — no outlier rejection, no HTTP staleness flag

KuCoin / MEXC / CoinGecko simple average; last price retained on outage. Venus is a separate BSC `eth_call`. Hub prices are largest-liquidity pool marks.

**Impact:** Advisory only for settlement, but `/protocol`, `volume_usd`, portfolio/trader P&L, and candle USD all follow these feeds (Chain C). #579 User-Agent is fixed. #687 DeFiLlama adapter still **throws on JSON null** — listing integrity, not fund loss.

### I-03 — Low: `include_unattested=1` and Swagger

Intentional ops flag. Swagger/OpenAPI always mounted — helps attackers map RE-01..RE-03. No HTTP security headers (`X-Content-Type-Options`, etc.) — Low, accepted at current TVL (SEC-J).

### I-04 — Info: no HTTP write API

Ingest is background-only. `seed-qa` writes via CLI + `DATABASE_URL`. Residual: unauthenticated compute/LCD abuse, not data-integrity writes.

### I-05 — Low: already-indexed pairs not re-verified against factory

Provenance is checked at discovery. A later DB row is trusted. Accepted if ops DB integrity holds. Foreign pairs are negative-cached 1h.

### FE-01 — High: `VITE_DEV_MODE` is not a production build reject

**Where:** `frontend-dapp/vite.config.ts` `assertBuildEnvGuards` rejects `VITE_DEV_MNEMONIC` outside development (unless `local-only`) and requires `VITE_WC_PROJECT_ID` in production. It does **not** reject `VITE_DEV_MODE=true`.

### Chain G2 — Application-layer resource exhaustion (primary new chain)

**Nodes:** RE-01 (`/gt/events` unbounded rows + full `pair_reserves`) + RE-02 (progress @ 60 RPS + live `GetDiscount`) + RE-03 (unbounded `tokens`/`pairs` on blacklist-check) + RE-04 (dApp 1 Hz progress + 15–60s refetch) + I389-25 class (no statement timeout) + public LCD (out-of-repo) + `PeerIpKeyExtractor` (NAT-shared buckets).

1. Attacker (or a listing partner, or a few dozen open `/` tabs) hits the **global** 60 RPS budget with mix of: wide `/gt/events` windows, progress polls with distinct `trader`s, and long `blacklist-check` lists.
2. Each request is “one HTTP hit” so the LCD-heavy 10 RPS governor **does not apply** except on `/route/solve` itself.
3. Indexer workers and the public Terra Classic LCD saturate. Honest `/route/solve` then hits the 30s timeout or 429. dApp indexer-outage copy appears (E2E-covered) — users cannot quote or trade through the official UI.
4. On-chain contracts keep working. Damage is **availability and LCD cost**, plus any keeper/bot that shares the same LCD.

**Why it chains:** request-count limits were built for #379/#363. GT (#646) and progress (#485) landed later on the cheap router. OWASP API4 is exactly “limits that count requests, not work.”

**Out-of-repo amplifier:** anyone can scrape `https://indexer.dex.cl8y.com` (listing adapters already do). No auth. CompressionLayer without a decompressed-size cap (prior I389-28) makes large GT responses cheaper to pull on the wire but not cheaper for Postgres.

**Severity: Medium** (High if TVL/listings make indexer downtime equivalent to “DEX down”). **Breaks:** RE-01 row cap + RE-02/RE-03 LCD-heavy + discount cache + GT statement timeout.
